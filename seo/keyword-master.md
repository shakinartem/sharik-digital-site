# Keyword Master Table — ШАРиК digital

Мастер-таблица семантики. Ею пользуемся **до** написания каждой статьи:
если на запрос уже отвечает страница — расширяем её, а не создаём вторую.

## Правила, которым подчиняется таблица

1. **Частотность не выдумывается.** Колонка пустая, пока не будет выгрузки
   из Яндекс Вордстата. Пустая ячейка честнее выдуманной цифры.
2. **Конкуренция** заполняется после ручного просмотра выдачи: дескриптор
   и сниппет конкурента не заменяют её.
3. **Одна страница — один интент.** Близкие запросы объединяются,
   а не размножаются в почти одинаковые статьи.
4. **Информационные запросы ведут в блог, коммерческие — на страницы
   услуг.** Смешивать нельзя: это разные целевые страницы.
5. Перед публикацией проверяем документацию Яндекса: функциональность
   платформы меняется, и устаревшая статья вредит больше отсутствующей.

### Решение по кластеру Wildberries / Ozon

Бриф предлагает раздельные страницы. **Не делаем**: интент почти одинаковый,
и две страницы «нужен ли мне свой магазин» размоют вес обеих.

Держим одну сильную `/blog/dlya-sellerov-wildberries` с отдельными
разделами по площадкам. Разделять только если в выдаче SERP по «магазин
для продавца wb» и «магазин для продавца ozon» действительно разные
страницы — это проверяется вручную.

## Часть 5. Проверка на каннибализацию

Перед созданием статьи ищем в `content/articles/` по смыслу запроса.

Если страница уже отвечает — не создаём вторую, а:

1. проверяем её в Метрике: есть ли показы и какой CTR;
2. если показы низкие при наличии спроса — обновляем title, description и H1;
3. если спроса нет — дополняем структуру и перелинковку;
4. только если страница отвечает на **другой** интент — создаём новую.

## Часть 6. Требования к каждой статье

Проверяется до публикации, иначе материал уходит в индекс сырым.

- [ ] Один H1, совпадающий с интентом страницы
- [ ] Title до 60–65 символов, уникальный, ключ не вставлен силой
- [ ] Description уникальный, не дублирует Title
- [ ] 2–5 ссылок на информационные материалы
- [ ] 1–2 ссылки на коммерческие страницы (`/yandex-kit`, `/sellers`)
- [ ] Один CTA в конце, не в каждом абзаце
- [ ] Минимум 2–4 осмысленных визуальных элемента для больших материалов
- [ ] Таблица — там, где сравнение действительно полезно
- [ ] Ссылки на официальную документацию Яндекса по техническим утверждениям
- [ ] Фраза «на момент обновления статьи», если функциональность меняется
- [ ] Проверено на дубли против соседних статей
- [ ] Объём соответствует интенту: FAQ — короче, инструкция — длиннее

## Часть 7. Порядок работы

1. **P1 по одному материалу за заход.** Не пакетом: пакет даёт
   одинаковые тексты и взаимная каннибализация.
2. После публикации — **проверка фактов по документации Яндекса**.
3. Смотрим Метрику через 2–4 недели: показы, CTR, позиции.
4. По данным решаем: что расширить, что удалить, что писать дальше.
5. Вторую волну планируем **по фактическим запросам**, а не по
   предположениям из этого файла.

## Что здесь не заполнено и почему

Колонки **Част.** и **Конк.** пустые намеренно. Заполняются из
Яндекс Вордстата и ручного просмотра выдачи. Числа, которых нет,
вписывать нельзя: они повлияют на приоритеты и введут в заблуждение.

Чтобы заполнить:

1. собрать частотность по списку запросов из таблицы в Вордстате;
2. для P1-запросов открыть выдачу Яндекса и отметить, кто в топе
   и какого типа это страницы;
3. проставить значения и вернуть файл в репозиторий.
